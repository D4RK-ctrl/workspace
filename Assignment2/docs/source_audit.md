## Observed schema and relationships

SQLite declares IDs, categories and timestamps as TEXT, coordinates/distance/rating as REAL, and experience/manual-update fields as INTEGER. It declares no primary-key or foreign-key constraints. CSV IDs/categories/timestamps are strings on read; outcome flags are numeric, delay is floating point with missing values. JSON event timestamps are strings; coordinates occur only on GPS pings. Timestamps inspected lack explicit timezone offsets; do not assume the workstation timezone is the source timezone.

Customers, drivers and restaurants each relate 1:N to orders. Orders relate 1:N to tickets, actions, interactions, events and interventions. Dispatch and outcomes are observed 1:1 by order ID; enforce that before future joins. Restaurant status is an incomplete snapshot, not a complete lifecycle log. Aggregate every child source to order grain before joining the proposed analytical table. Missing child rows imply zero only if capture completeness is established.

## Observed data quality and checkpoint comparison

For a **diagnostic comparison only**, retain the first SQL row per order as the classroom notebook does, normalize final-status case, parse timestamps, and select delivered orders with promise and completion timestamps. This does not approve keep-first as a business rule.

| Raw / unique orders | 1,603 / 1,600 | Matches lecture checkpoint; no fully identical order rows |
| Cancelled / delivered | 68 / 1,532 | Delivered includes 5 `Delivered` case variants |
| Delivered missing completion | 37 | Total SQL completion nulls = 105, including cancellations |
| Measurable delivered / late (>0 minutes) | 1,495 / 843 | 56.38796%; matches approximate rate; not fully lifecycle-validated |
| Median delay among late orders | 8.02723 minutes | Differs from lecture ~7.9; no adjustment made |

| Promise before creation / delivery before pickup | 4 / 5 | Counts after diagnostic deduplication; overlap not assumed |
| Order date range | 2026-08-01 11:02 to 2026-08-28 23:33 | Historical snapshot; wall-clock freshness is not automatically appropriate |
| Estimated distance range | 0.5 to 45 km | Estimated distance, not measured driver travel |

Conflicting order repeats are `O00120` (`severe` / `medium` traffic), `O00723` and `O01302` (`medium` / `high`). They affect attribution by traffic; no version field identifies a winner. Raw traffic also contains 3 `HIGH` values. No non-null order customer/restaurant/driver FK is orphaned; 3 restaurant and 3 driver links are null.

Support has `Late Delivery`, `late_delivery ` and `ETA issue` variants. Deduplicating ticket IDs, lowercasing and replacing spaces with underscores **without trimming** selects 37 measurable complaint orders and yields 14.10702 minutes median delay. Adding trimming selects 38 and yields 14.77964 minutes. The ~14.1 lecture checkpoint therefore depends on category handling; neither value should be forced. `ETA issue` must not be silently equated with `eta_changed`.

Telemetry types are `assigned` (1,600), `gps_ping` (5,371), `picked_up` (1,532), `delivered` (1,532). No restaurant-arrival event exists. There are **3,639 GPS pings strictly between SQL pickup and completion**, contradicting the lecture gist's blanket claim of no transit pings. This does not establish reliable continuous tracking or observed arrival. Telemetry provides delivery events for all 37 orders missing SQL completion; for the 1,495 non-null SQL completions, delivery timestamps agree. Filling SQL gaps requires an approved source policy.

Dispatch contains 95 non-null `reassigned_at` values; 95 current-driver values differ from SQL driver values. Current and original assignments must remain distinct. `reassigned_at` does not provide a complete reassignment count. Restaurant-status updates range from 5.9 hours before to 35 minutes after order creation; none of the inspected unique status updates follows recorded delivery. Whether an early update is stale or mislinked needs owner clarification.

App actions contain 2,217 `ETA_VIEWED`, 138 `SUPPORT_OPENED`, 10 `CANCEL_ATTEMPTED`; customer links agree with SQL. Interventions contain 155 `DRIVER_REASSIGNMENT`, 116 `RESTAURANT_CONTACT`, 95 `PRIORITY_DISPATCH`, 64 `CUSTOMER_CREDIT`. Order events instead contain 1,600 creation, 1,600 pickup and 1,495 delivery events plus 260 intervention-like events across a different vocabulary, including `ETA_MESSAGE` and `REFUND_OFFER`. This is an unresolved lineage difference, not extra actions to append.

Outcome buckets are 843 late, 652 on-time, 68 cancelled, 37 unknown. Available outcome delays agree with SQL-derived delay within 0.011 minutes; this does not resolve the existing chronology errors or prove derivation independence.
